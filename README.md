# samr-report-autouploader

**检验检测报告编号上传系统 · 自动化上传助手（GUI 版）**

通过 Chromium 远程调试协议（CDP）自动控制「检验检测报告编号上传系统」Electron 应用，完成从**登录 → 下载数据模板 → 填写报告数据 → 导入数据表格 → 生成并导入电子原件 PDF → 数据上传 → 回写上传状态**的全流程自动化。

主程序：[`auto_upload_cdp_gui.py`](./auto_upload_cdp_gui.py)（增强版 Tkinter GUI）

## 功能概览

### 登录阶段

| 功能 | 说明 |
| --- | --- |
| 应用复用检测 | 启动时先检测应用是否已打开（调试端口 + 进程名双层检测），已打开则复用该实例，不重复启动 |
| 已登录跳过 | 若检测到已处于登录后（首页）状态，连登录流程一起跳过，直接执行登录后逻辑 |
| 自动启动应用 | 未打开时带 `--remote-debugging-port` 启动上传系统 exe |
| 自动填写登录表单 | 用户名 / 密码自动填入，并勾选「记住账号」 |
| 图形验证码 OCR | 基于 `ddddocr` 自动识别并填入；支持服务端预校验、换图重试；失败自动降级人工输入 |
| 邮箱安全验证 | 检测到「邮箱安全验证」页后暂停自动化点击，等待人工在窗口中完成验证后**自动继续**（默认上限 10 分钟） |
| 首次启动配置弹窗 | 自动创建报告备份根目录 → 点「选择文件夹」→ 点「完成配置」，全程无人值守 |

### 登录后流程（首页自动执行）

| 步骤 | 说明 |
| --- | --- |
| 1. 下载表格模板 | 点击「下载表格模板」；下载前先关闭已被 Excel/WPS 打开的模板 xlsx，释放文件锁 |
| 2. 系统保存对话框 | 自动定位原生「保存」对话框，强制保存到 `%ProgramData%\AreportFile`，处理「文件已存在，是否替换」确认框 |
| 3. 定位模板文件 | 依次尝试：对话框完整路径 → 应用日志 `savePath` 解析 → 候选目录扫描 |
| 4. 采集已上传报告编号 | 进入「已上传报告管理 → 全部报告」，逐页翻页采集全部报告编号后切回上传菜单，用于**去重过滤** |
| 5. 自动填写模板数据 | 调用 HashReport 接口拉取待上传数据，按 `ft` / `lt` / `qj` 三种报告类型展开，流式写入 xlsx（内存恒定，支持 20 万行级）；已上传的编号自动排除 |
| 6. 打开 xlsx | 用系统默认程序打开填写好的模板供预览（超过 1 万行自动跳过，避免 Excel 卡死） |
| 7. 关闭 xlsx | 等待数秒后自动关闭模板文件，释放文件锁，为导入做准备 |
| 8. 导入数据表格 | 点击「选择数据表格导入」→ 原生「打开」对话框选中该 xlsx → 处理「编号失效确认」弹窗 |
| 9. 生成 OrigDoc PDF | 按报告编号从服务器并发下载报告原件 PDF（默认 12 线程），清空并写入 `%ProgramData%\AreportFile\OrigDoc`；任一失败即终止（零容忍） |
| 10. 确认导入结果 | 软确认页面上已完成数据表格导入（超时仅提示，不阻断） |
| 11. 导入电子原件文件夹 | 点击「选择报告电子原件文件夹导入」→ 原生文件夹对话框选中 `OrigDoc` → 校验页面显示「已选择文件夹」 |
| 12. 数据上传 | 点击「数据上传」→ 等待 10 秒倒计时 → 点击确认弹窗中的「数据上传」按钮 |
| 13. 回写上传状态 | 全部完成后调用 `MarkHashReportUploaded` 接口，把本轮报告状态从 1（要上传）批量改为 2（已上传），幂等 |

### 无数据自动结束

若接口无「要上传」数据（或过滤已上传后为空），流程记为**正常结束**（`FLOW_STOP`），自动跳过写表、打开、导入、上传等后续步骤，不报错。

### GUI 能力

- **启动 / 暂停 / 继续 / 重新执行** 状态机（含防双击竞态锁）
- 线程安全日志管道：后台 `print` 批量落入日志框，长任务进度单行原地刷新，日志上限 2000 行
- 设置对话框：软件路径、用户名、密码（带眼睛切换明文）、调试端口
- 配置持久化到 `gui_config.json`（密码以 `b64:` 前缀混淆存储）
- 「重载代码」热重载功能已注释停用（代码保留备查，取消注释可恢复）

## 运行环境与依赖

- **操作系统**：Windows（原生保存/打开/文件夹对话框自动化、文件锁检测依赖 Win32 API）
- **Python**：3.x（打包环境实测 Python 3.14.6 + PyInstaller 6.22.3）
- **被控应用**：检验检测报告编号上传系统（Electron，支持远程调试端口）

### Python 依赖

```bash
pip install requests websocket-client ddddocr Pillow openpyxl
```

| 依赖 | 用途 | 必需性 |
| --- | --- | --- |
| `requests` | HashReport 接口调用 | 必需 |
| `websocket-client` | CDP WebSocket 通信 | 必需 |
| `ddddocr` + `Pillow` | 图形验证码自动识别 | 可选（缺失时降级人工输入验证码） |
| `openpyxl` | 读取模板表头 / 写表自检 | 可选（缺失时跳过部分内容检查） |
| `wmi` | 进程级关闭占用 xlsx 的兜底 | 可选（缺失时退化） |

### 模块依赖

主脚本引用同目录下的 [`auto_upload_cdp.py`](./auto_upload_cdp.py)：

```python
import auto_upload_cdp as _cdp_mod
CDPClient = _cdp_mod.CDPClient          # CDP 客户端
JS_CLICK_LOGIN = _cdp_mod.JS_CLICK_LOGIN  # 点击登录按钮的 JS 脚本
```

请确保 `auto_upload_cdp.py` 与 `auto_upload_cdp_gui.py` 位于同一目录。

## 快速开始

1. **配置软件路径**（首次运行会自动弹出「设置」）：
   - 点击「设置」→「浏览…」选择上传系统 exe
   - 填写登录用户名 / 密码、调试端口（默认 `9222`）
   - 点击「保存」
2. **启动自动化**：
   ```bash
   # 方式一：双击
   run_gui.bat

   # 方式二：命令行
   python auto_upload_cdp_gui.py
   ```
3. 点击「启动」，按日志提示观察流程；出现邮箱验证时在应用窗口手工完成后会自动继续。
4. 流程结束后可点击「**重新执行**」开始下一轮（会清理上一轮中转数据）。

## 完整自动化流程

### 启动前预检测（三分支）

```
应用是否已打开？
├─ 已打开且已登录  → 复用实例，跳过登录，直接执行登录后逻辑
├─ 已打开未登录    → 复用实例 → 登录 → 登录后逻辑
└─ 未打开          → 启动新实例（带调试端口）→ 连接 CDP → 登录 → 登录后逻辑
```

检测层次：
1. 调试端口 + CDP 页面特征（最准确，确认是本应用）
2. 进程名匹配 `tasklist`（兜底，检测手动打开、未带调试端口的情况）
3. 启动新实例前：端口占用者是否为已挂载调试端口的本应用（是则沿用原端口，否则找空闲端口）

### 登录后步骤清单（默认 17 步）

**登录阶段**（视分支 5~7 步）：

1. 启动/连接上传系统应用（CDP）
2. 等待登录表单加载
3. 填写用户名 / 密码并勾选「记住账号」
4. 自动识别图形验证码并提交登录
5. 等待「邮箱安全验证」（人工完成后自动继续）
6. 处理「首次启动配置」弹窗

**首页阶段**（`POST_LOGIN_STEPS` + `IMPORT_STEPS`，由 `AUTO_IMPORT_TEMPLATE` 开关控制后半段）：

1. 点击「下载表格模板」按钮
2. 在保存对话框中点击「保存」按钮
3. 定位刚刚下载好的 .xlsx 文件
4. 采集「已上传报告管理 / 全部报告」所有分页的报告编号并切回上传菜单
5. 在模板 xlsx 中自动填写数据（排除已上传报告编号）
6. 用系统默认程序打开该 .xlsx 文件
7. 等待几秒后关闭该 .xlsx 文件
8. 点击「选择数据表格导入」按钮
9. 在「打开」对话框中选中该 .xlsx 并点「打开」
10. 处理导入后的「编号失效确认」弹窗
11. 按报告编号生成 OrigDoc PDF 文件
12. 确认页面上已完成数据表格导入
13. 点击「选择报告电子原件文件夹导入」按钮
14. 在文件夹对话框中选中 OrigDoc 并点「选择文件夹」
15. 点击「数据上传」按钮
16. 等待 10 秒后点击弹窗里的「数据上传」确认按钮
17. 全部流程结束后，把 hashReport 状态回写为「已上传」

### 模板数据填写规则

- **数据来源**：`POST /api/Login/CheckLogin` 取 token → 带 `Authorization` 调 `GetHashReportUploadedList`（`Status=1` 待上传）
- **三种报告类型前缀**：`ft` / `lt` / `qj`；某类型 `{前缀}UploadStatus == 1` 时生成一行，三个都是 1 则一条数据生成三行
- **字段映射**（以 `ft` 为例，`lt` / `qj` 同理）：

  | xlsx 列 | 字段 |
  | --- | --- |
  | 报告编号 | `ftReportNo` |
  | 授权签字人 | `ftReportQF` |
  | 报告签发日期 | `ftReportDate`（取 `YYYY-MM-DD`） |
  | 报告签发年份 | `ftReportDate` 截取年份 |
  | 哈希值 | 留空（系统自动生成） |
  | 编号是否有效 | 默认「是」 |
  | 委托人 | `ftReportWT` |
  | C2 检验检测机构名称 | `广东优捷检测科技有限公司`（常量 `FILL_ORG`） |

- **去重**：写表前从「已上传报告管理 / 全部报告」逐页采集已上传编号，写表与 PDF 下载共用同一份中转数据，自动排除
- **大批量优化**：接口逐页拉取（每页 1000 条）→ 展开为扁平行写入磁盘 JSONL（`auto_upload_rows.jsonl`）→ 写表 / PDF 下载各自流式读取，**内存不随数据量增长**
- **PDF**：`{域名}/Server/Upload/Formal/TestCheckOrder/{T_AutoID}/UploadPic/{ltReport}`，文件名用报告编号，下载前清空 OrigDoc 旧文件

## 配置说明

### 配置文件

`gui_config.json`（开发时在脚本目录，打包后在 exe 旁），首次由「设置」保存生成：

```json
{
  "EXE_PATH": "C:\\...\\上传系统.exe",
  "USERNAME": "你的账号",
  "PASSWORD": "b64:xxxx（保存时自动混淆，读取时解码）",
  "DEBUG_PORT": 9222,
  "KEEP_APP_OPEN": true,
  "AUTO_DOWNLOAD_TEMPLATE": true,
  "AUTO_OPEN_TEMPLATE": true,
  "AUTO_FILL_TEMPLATE": true,
  "CLOSE_XLSX_AFTER_OPEN": true,
  "AUTO_IMPORT_TEMPLATE": true
}
```

> 设置界面目前只暴露路径 / 账号 / 密码 / 端口；功能开关统一取 `DEFAULT_CONFIG` 默认值（当前均为 `True`）。需要调整请直接改 `gui_config.json` 或代码默认值，改完重启生效。

### 主配置项（`DEFAULT_CONFIG`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `EXE_PATH` | `""` | 上传系统 exe 路径，为空时进入页面强制要求先「设置」 |
| `USERNAME` / `PASSWORD` | — | 登录账号；密码持久化时以 `b64:` 前缀混淆 |
| `DEBUG_PORT` | `9222` | CDP 远程调试端口 |
| `KEEP_APP_OPEN` | `true` | 登录成功后保留应用与 CDP 连接；`false` 流程结束关闭应用 |
| `AUTO_DOWNLOAD_TEMPLATE` | `true` | 进入首页后自动执行「下载表格模板」流程 |
| `AUTO_OPEN_TEMPLATE` | `true` | 模板下载完成后用系统默认程序打开该 .xlsx |
| `AUTO_FILL_TEMPLATE` | `true` | 打开该 .xlsx 之前自动按规则填写数据 |
| `CLOSE_XLSX_AFTER_OPEN` | `true` | 打开 xlsx 后等待几秒自动关闭（释放文件锁） |
| `AUTO_IMPORT_TEMPLATE` | `true` | 关闭 xlsx 后自动点「选择数据表格导入」并选中该文件导入 |

### 主要超时常量（脚本配置区，改代码生效）

| 常量 | 默认 | 说明 |
| --- | --- | --- |
| `STARTUP_TIMEOUT` | 30s | 等待应用启动并打开调试端口 |
| `CAPTCHA_TIMEOUT` | 120s | 人工输入验证码等待上限 |
| `CAPTCHA_MAX_ROUNDS` | 8 | 自动识别最多换图重试轮数 |
| `EMAIL_VERIFY_TIMEOUT` | 600s | 等待人工完成邮箱验证上限 |

| `UPLOAD_CONFIRM_DELAY` | 10s | 上传确认弹窗出现后等待倒计时的秒数 |

## 验证码与邮箱验证

### 图形验证码（ddddocr）

1. 注入 JS 捕获验证码图片 → `ddddocr` 识别（多档补白预处理：24/40/48/56/64/80）
2. 可选服务端接口预校验候选答案（`CAPTCHA_PRECHECK`），确认无误后再填入并点登录
3. 登录被拒（提示含「验证码」）则换一张新图重试，最多 `CAPTCHA_MAX_ROUNDS` 轮
4. 连续失败 → **降级为人工**：状态切换为「等待你输入验证码」，在应用窗口填好后脚本检测到并自动点登录
5. 未安装 `ddddocr` 时直接走人工路径，启动日志会给出 `pip install ddddocr` 提示

### 邮箱安全验证

1. 提交登录后在 8 秒窗口内探测验证页；未出现则走正常路径
2. 检测到验证页 → 状态切换为「等待邮箱验证」，**自动化暂停一切点击/输入**，仅只读轮询
3. 请在应用窗口手工完成：获取验证码 → 输入 → 验证并登录
4. 验证完成（验证页特征消失 + 出现首页标志）→ **自动继续**后续上传步骤，无需点「继续」
5. 超过 10 分钟未完成 → 置为出错并提示，可点「重新执行」重试；等待期间状态栏实时显示已等待秒数

### 使用打包脚本

双击 [`build.bat`](./build.bat)（依赖本机已安装的 PyInstaller；脚本内注释了 Python 3.14 环境的两个 workaround）：

```bat
set OPENBLAS_NUM_THREADS=1
set OMP_NUM_THREADS=1
E:\python\Scripts\pyinstaller.exe --clean "自动上传检测报告.spec"
```

产物：单文件、无控制台 exe，名称 **`报告自动上传助手.exe`**。

### 打包配置要点（[`自动上传检测报告.spec`](./自动上传检测报告.spec)）

- **按需收集**：仅打包 `ddddocr` 的 `.onnx` 模型与 `onnxruntime` 原生 DLL，其余交给静态分析
- **显式排除**大而无用的依赖（`PyQt5/PySide*`、`pandas`、`transformers` 等）
  - 特别注意：`PyQt5` 自带旧版 VC 运行库（`msvcp140.dll 14.26`）会顶掉系统新版，导致 `onnxruntime`/`opencv` 初始化时触发 `0xC0000005`，exe 双击即崩溃
- `console=False`：无控制台运行；`print`/`traceback` 已重定向到 GUI 日志框，仍可观测
- **勿用 `collect_all`**：全量收集会把 exe 撑到 270MB+ 并引入上述崩溃问题

> 如重装/升级 PyInstaller，需重新应用 build.bat 注释中提到的「隔离禁用补丁」。

## 常见问题

**Q：提示「未设置软件路径」？**  
首次运行会自动弹出「设置」，点「浏览…」选择上传系统 exe 后保存。

**Q：提示「未安装 ddddocr，验证码将需要人工输入」？**  
`pip install ddddocr Pillow` 后重启；或不安装，在应用窗口手工输入验证码即可，脚本会检测到已填写并继续。

**Q：一直停在「等待邮箱验证」？**  
在应用窗口完成邮箱验证即可自动继续；经常超时可调大脚本配置区的 `EMAIL_VERIFY_TIMEOUT`（默认 600 秒）。

**Q：模板下载保存失败 / 提示文件正在使用？**  
下载前脚本会尝试关闭已打开的模板 xlsx 并处理「是否保存」弹窗；若仍被占用，请手动关闭 Excel/WPS 中打开的模板后点「重新执行」。

**Q：应用已手动打开（未带调试端口）怎么办？**  
脚本检测到进程在跑后会启动一个**带调试端口的新实例**；建议先关闭旧实例避免混淆。若端口已被本应用占用，会沿用原端口。

**Q：本轮没有需要上传的数据？**  
日志会提示「本轮无需上传，流程正常结束」，属于正常情况（如全部已上传），可点「重新执行」开始下一轮。

**Q：「重载代码」按钮去哪了？**  
热重载功能已注释停用（代码保留在源文件中备查）。需要时取消注释 `hot_reload_module`、`run_post_login_flow` 及 GUI 按钮相关代码即可恢复。
